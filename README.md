# Telegram Mini App — магазин-конструктор

Готовый магазин для Telegram, который разворачивается на своём VPS за 5 минут и
настраивается под любую нишу без правки кода: от классической корзины до витрины,
где покупка идёт только через личку менеджера.

- **Зависимостей нет.** Нужен только Node.js 18+. Ни базы данных, ни npm-пакетов.
- **Данные — файлы.** Весь магазин это папка `data/`: четыре JSON и картинки.
  Бэкап — `tar czf backup.tgz data`, переезд — скопировать папку.
- **Бот в том же процессе.** Long polling, вебхук настраивать не нужно.
- **Всё меняется из админки.** Тема, режим продаж, тексты, поля формы, уведомления.

## Установка на Debian / Ubuntu

> 🔰 **Первый раз работаете с сервером?** Есть подробный пошаговый гайд с бесплатным
> доменом DuckDNS, скриншотными объяснениями каждой команды и разбором типичных
> ошибок: **[SETUP.md](SETUP.md)**. Раздел ниже — краткая версия для тех, кто уже
> умеет в SSH.

Нужен: чистый VPS (Debian 11/12 или Ubuntu 22.04/24.04), домен с A-записью на его IP
(без него Telegram не пустит мини-апп — подойдёт бесплатный `*.duckdns.org`),
и токен бота от [@BotFather](https://t.me/BotFather).

Вебхук настраивать не нужно: бот работает через long polling.

```bash
apt update && apt install -y git
git clone <адрес-репозитория> /root/tg-shop && cd /root/tg-shop
bash install.sh
```

Скрипт спросит четыре вещи (токен бота, домен, пароль админки, порт) и сам:
поставит Node.js, создаст системного пользователя `tgshop`, разложит файлы в
`/opt/tg-shop`, поднимет systemd-сервис, настроит nginx и выпустит
HTTPS-сертификат Let's Encrypt.

В конце он напечатает адреса витрины и админки и пароль. **Сохраните пароль** —
второй раз он не показывается.

### Что сделать в BotFather

1. `/newapp` → выбрать бота → указать URL: `https://ваш-домен/`
2. `/setmenubutton` → выбрать бота → указать ту же ссылку на мини-апп
3. Скопировать ссылку вида `https://t.me/вашбот/приложение` — она понадобится
   в админке, вкладка **Канал**, чтобы работала публикация товаров.

### Первые шаги в админке

Откройте `https://ваш-домен/admin.html`, введите пароль. Дальше по вкладкам:

1. **Бренд** — название, эмодзи или логотип, описание.
2. **Тема** — выбрать пресет, потом при желании подкрутить цвета.
3. **Продажи** — режим работы и контакт менеджера.
4. **Уведомления** — вписать свой `chat_id` и нажать «Отправить тестовое
   уведомление». Пока тест не прошёл — заказы до вас не дойдут.
5. **Товары** — наполнить каталог.

> **Важно про уведомления.** Telegram запрещает боту писать первым тому, кто с ним
> ещё не общался. Прежде чем вписывать свой ID, напишите боту `/start`. Свой
> числовой ID можно узнать, отправив боту команду `/id`.

## Режимы продаж

Переключаются одним селектом на вкладке **Продажи** — это главный тумблер, который
превращает один и тот же код в разные продукты.

| Режим | Что видит покупатель | Кому подходит |
|---|---|---|
| **Корзина + оформление** | Корзина, форма заказа, заказ падает менеджеру в Telegram | Обычный магазин |
| **Только через менеджера** | Корзины нет вообще, кнопка ведёт в личку продавца с готовым текстом | Услуги, штучный товар, торг |
| **Заявка по товару** | Корзины нет, но есть форма — клиент оставляет контакты по одному товару | Заявки, предзаказы, аренда |
| **Витрина без покупки** | Только каталог, кнопок покупки нет | Портфолио, шоурум, меню |

## Что настраивается без кода

**Бренд:** название, эмодзи, логотип, подзаголовок, стиль шапки, описание в профиле,
произвольные ссылки в профиле (соцсети, Avito, канал, сайт).

**Тема:** 8 пресетов оформления (Бруталист, Конструктивизм, Баухаус, Неон,
Швейцарский, Моно, Мягкий, Кислота), 7 цветов по отдельности, шрифт, масштаб текста,
скругления, толщина рамок, капслок, плотность вёрстки, число колонок, стиль карточек
(рамка / без рамки / жёсткая тень / наклейки с наклоном), пропорции фото, косые срезы,
зерно плёнки, бегущая строка, режим анимаций, произвольный CSS.

**Каталог:** показывать ли поиск, категории, сортировку и счётчик; сортировка по
умолчанию; показ остатков и порог «осталось мало»; прятать ли раскупленное; бейдж
хитов и его текст; текст пустого каталога.

**Продажи:** режим, тексты кнопок, символ валюты и его позиция, скрытие цен с заменой
на «цена по запросу», минимальная сумма заказа, включение корзины и избранного,
ссылка на менеджера и поддержку, шаблоны сообщений с подстановками.

**Форма заказа:** какие поля спрашивать (имя, телефон + обязательность, ссылка, email,
комментарий, адрес), списки способов оплаты и доставки, галочка согласия с
собственным текстом, заголовок и текст финального экрана.

**Уведомления:** несколько получателей, отдельные тумблеры на заказ / на обращение к
менеджеру / на нового пользователя бота, ссылка на профиль клиента, беззвучный режим.

**Бот:** приветствие, текст кнопки, ответ на `/help`, копия заказа покупателю в чат
с собственным шаблоном чека.

**Канал:** канал для публикации, ссылка мини-аппа, шаблон поста с переменными, текст
кнопки в посте.

**Прочее:** режим обслуживания с текстом-заглушкой, локаль, часовой пояс,
экспорт/импорт всей конфигурации в JSON.

Переменные в шаблонах: `{product}`, `{price}`, `{items}`, `{total}`, `{shop}`,
`{name}`, `{order}`, `{description}`, `{category}`.

## Эксплуатация

```bash
systemctl status tg-shop      # состояние
systemctl restart tg-shop     # перезапуск
journalctl -u tg-shop -f      # живые логи
```

Бэкап и восстановление:

```bash
tar czf backup.tgz -C /opt/tg-shop data
tar xzf backup.tgz -C /opt/tg-shop && systemctl restart tg-shop
```

Обновление кода:

```bash
cd /root/tg-shop && git pull && bash install.sh
```

`install.sh` идемпотентен: он не трогает `data/` и `.env`, поэтому повторный запуск
безопасен и работает как обновление.

### Клонирование магазина под другого клиента

Админка → **Ещё** → «Экспорт» сохранит настройки и товары в JSON. На новом сервере
после установки — «Импорт». Фотографии при этом не переносятся (они лежат в
`data/images`), их можно скопировать отдельно: `rsync -a data/images/ new-server:/opt/tg-shop/data/images/`.

## Long polling или webhook

По умолчанию бот работает на **long polling** — и для одного сервера это осознанный
выбор, а не упрощение.

Частое заблуждение: «polling медленный». Медленный — *короткий* polling, когда бот
дёргает сервер по таймеру. Наш вызывает `getUpdates` с `timeout=30`, то есть держит
соединение открытым, и Telegram отдаёт сообщение в тот же момент, когда оно пришло.
Разница в задержке с вебхуком — единицы миллисекунд.

Второе, что стоит учитывать: **уведомления о заказах — это исходящие `sendMessage`,
и транспорт на них не влияет вообще**. Скорость «отстука» менеджеру одинакова
в обоих режимах.

| | long polling | webhook |
|---|---|---|
| Работает до выпуска сертификата | да | нет |
| Переживает падение nginx / протухший сертификат | да, переподключится | нет, апдейты теряются |
| Несколько экземпляров за балансировщиком | нет, `409 Conflict` | да |
| Потолок пропускной способности | 100 апдейтов за запрос, последовательно | до 100 параллельных соединений |
| Нужен публичный HTTPS на 443/80/88/8443 | нет | да |

Вебхук объективно выигрывает в одном: горизонтальное масштабирование. Telegram
запрещает параллельные `getUpdates` под одним токеном, поэтому раскинуть бота на
несколько подов можно только вебхуком. Именно поэтому на нём сидят крупные боты —
но у магазина на одном VPS этой задачи нет.

### Как включить вебхук

Если всё же нужен — он реализован, включается одной строкой в `.env`:

```
BOT_MODE=webhook
```

и `systemctl restart tg-shop`. Требования: `PUBLIC_URL` начинается с `https://`
и сертификат валиден. Бот сам вызовет `setWebhook` на `PUBLIC_URL/api/webhook`.

Отдельный секрет заводить не нужно: он выводится из `BOT_TOKEN` + `ADMIN_TOKEN`,
передаётся Telegram в заголовке `X-Telegram-Bot-Api-Secret-Token` и сверяется на
каждом запросе — без этого адрес был бы открытым приёмником поддельных сообщений.

Если `setWebhook` не прошёл (нет HTTPS, сертификат протух, домен не резолвится) —
бот **не падает, а автоматически откатывается на long polling** и пишет причину
в лог. Обратно переключиться: убрать строку из `.env` и перезапустить, вебхук
снимется сам.

## Совместимость с версиями Telegram

Витрина рассчитана на старые клиенты: всё, что появилось позже базовой версии,
вызывается только после проверки `isVersionAtLeast`, а при отсутствии поддержки
функция просто не включается — экран не ломается.

| Возможность | Нужен Bot API | Если клиент старее |
|---|---|---|
| `disableVerticalSwipes` — свайп по галерее не сворачивает мини-апп | 7.7 | свайп вниз может свернуть приложение |
| `safeAreaInset` / `contentSafeAreaInset` | 8.0 | отступы берутся из CSS `env(safe-area-inset-*)` |
| Произвольный hex в `setHeaderColor` | 6.9 | шапка красится ключевым словом `bg_color` |
| `BackButton`, `HapticFeedback`, `setBackgroundColor` | 6.1 | шторки закрываются крестиком, вибрации нет |
| `MainButton`, `viewportStableHeight` | базовые | — |

Про горизонтальные свайпы отдельно: на iOS свайп от самого края экрана — это
системный жест «назад», и карусель у края экрана может его поймать. Поэтому
галерея не прижата к краю (у шторки есть внутренний отступ), а под ней всегда
показаны точки и счётчик кадров — это подсказывает, что элемент листается, и
пользователь начинает жест не от кромки. Полностью отключить системный жест из
веба нельзя ни одним SDK.

## Безопасность

- Админка защищена одним токеном из `.env`, сравнение — константное по времени.
- Заказы принимаются с проверкой подписи `initData`; заказ без валидной подписи
  помечается в уведомлении как неподтверждённый.
- Цены и названия для заказа берутся из базы, а не из того, что прислал клиент.
- На публичные ручки стоит rate limit по IP.
- Сервис работает под непривилегированным пользователем, systemd даёт ему доступ
  на запись только в `data/`.

Что стоит сделать дополнительно: закрыть SSH по паролю, поднять ufw, и не давать
пароль от админки лишним людям — прав внутри неё нет, она полностью админская.

## Прежний деплой на Netlify

Папка `netlify/` осталась от первой версии проекта. **Она не совместима с текущей
схемой настроек** (там старый плоский формат, без режимов продаж и тем) и не

просто удалить.
